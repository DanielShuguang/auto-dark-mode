# ADR-0002：改用 Tauri 2 + Vue 3

- **状态**：已接受
- **日期**：2026-11-09
- **取代**：[ADR-0001](0001-tech-stack.md) 中「Rust + 手写 Win32 单进程」的实现方式
- **保留**：ADR-0001 中关于「Windows 无公开主题 API，只能注册表 + 广播」的结论仍然有效

## 背景

ADR-0001 选择了零依赖 Rust + 手写 Win32 FFI，理由是内存与体积。

实现过程中暴露出两个问题：

1. **样板代码量远超预期**。托盘图标（`NOTIFYICONDATAW`、`Shell_NotifyIcon`）、
   隐藏顶层窗口、消息循环、程序化构建的设置窗口、DPI 缩放、单实例互斥，
   合计约 2400 行，其中大部分与业务无关。
2. **失败模式隐蔽**。例如 `CreateMutexW` 新建成功时不清零 `LastError`，
   导致程序误判「已有实例」而静默退出（退出码 0、无窗口、无日志），
   排查成本很高。

## 决策

改用 **Tauri 2 + Vue 3 + TypeScript**：

| 能力 | 由谁提供 |
|---|---|
| 窗口、托盘、菜单 | Tauri |
| 开机自启 | `tauri-plugin-autostart` |
| 设置界面 | Vue 3（WebView2） |
| 配置持久化 | serde JSON |
| 主题注册表读写 + 广播 | 保留少量手写 FFI（已验证可用） |
| 日出日落 / 历法 / 定位 | 保留原有纯逻辑模块（带单元测试） |

## 权衡

- **代价**：常驻内存从 3–6 MB 升到约 10–20 MB；安装包体积增大；
  依赖 WebView2（Windows 11 自带）。
- **收益**：托盘与窗口相关的样板代码不再自己维护；UI 迭代成本大幅下降；
  失败模式从「Win32 静默失败」变成「框架层显式错误」。
- 仍在 30 MB 预算内，但余量从 5 倍降到 1.5–3 倍。若后续内存超预算，
  可退回 ADR-0001 的方案（原实现已删除，但结论与代码结构在 ADR 中有记录）。

## 遗留

- 新工程尚未编译验证：开发环境无法访问 npm / crates.io。
